BASIC AUTH

Basic Authentication ketma-ketligi

Bu eng sodda usul. Har requestda username va password header orqali yuboriladi.

Request header
Har safar credential yuboriladi
GET /api/products/ HTTP/1.1
Host: example.com
Authorization: Basic dXNlcm5hbWU6cGFzc3dvcmQ=
Request Auth tekshiruvi
Client har requestda login ma’lumotini yuboradi → server credential’ni ajratadi → to‘g‘ri bo‘lsa user taniladi.
1
Client username va password’ni Base64 ko‘rinishda yuboradi.
2
Server header ichidan credential’ni ajratadi.
3
Django auth tizimi orqali login va parol tekshiriladi.
4
To‘g‘ri bo‘lsa user taniladi, noto‘g‘ri bo‘lsa 401 qaytadi.
Afzalligi
Test va tez prototip uchun juda sodda.
Kamchiligi
Har requestda login-parol yuboriladi. Production uchun yaxshi odat emas.

CORS

CORS nima?

Agar frontend bir joyda, backend boshqa joyda bo‘lsa, browser “bu requestga ruxsat bormi?” deb tekshiradi. Shu joyda CORS kerak bo‘ladi.

Frontend
Masalan Vercel
Browser
Ruxsat bormi deb tekshiradi
Backend
Masalan Render API
CORS yo‘q bo‘lsa
Browser requestni bloklab qo‘yishi mumkin.
CORS to‘g‘ri bo‘lsa
Frontend API bilan bemalol gaplashadi.
Qachon kerak?

Frontend va backend ajralgan bo‘lsa

Masalan frontend localhost:3000, backend esa onrender.com bo‘lsa.

Qachon kerak emas?

Hammasi bitta joyda bo‘lsa

Agar frontend va backend bitta domen ostida ishlasa, CORS muammo bo‘lmasligi mumkin.

CORS SETTINGS

CORS ni qanday yozamiz?

Juda sodda variant: corsheaders ni app va middleware ga qo‘shamiz, keyin allowed origin larni yozamiz.

settings.py
CORS sozlamasi
INSTALLED_APPS = [
    # ...
    'corsheaders',
]

MIDDLEWARE = [
    'corsheaders.middleware.CorsMiddleware',
    'django.middleware.security.SecurityMiddleware',
    # ...
]

CORS_ALLOWED_ORIGINS = [
    'http://localhost:3000',
    'https://your-frontend.vercel.app',
]

ALLOWED_HOSTS, static, CORS yoki boshqa muammo bo‘lganmi.
