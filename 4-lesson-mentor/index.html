1-dars
Swagger

2-dars
CRUD yozish usullari

3-dars
Searching, Filtering, Pagination

Student endpointni qulayroq, foydali va real loyiha talablariga yaqin qilish uchun query parametrlar bilan ishlashni bilishi kerak.

Teacher iborasi: “Biz avval API ni yaratishni o‘rgandik, keyin uni turli usullarda yozishni o‘rgandik, endi esa uni foydalanuvchi uchun qulayroq qilishni o‘rgandik. Bugun shu uchalasini bitta loyiha ichida birlashtiramiz.”
Step by step

Dars o‘tish xaritasi

1-qadam · kirish 6–8 min

1–2–3-darslarni qisqa recap qiling

Har bir darsdan faqat asosiy nuqtalarni qaytaring. Maqsad — studentning xotirasini faollashtirish. Juda uzoq nazariya emas, balki asosiy vazifalar va ularning o‘zaro bog‘liqligini eslatish kerak.

Savol bering: “Swagger nimaga kerak?”, “CRUD nima?”, “Search va filter o‘rtasida farq nima?”, “Pagination nega kerak?”
2-qadam · chuqur tahlil 12–15 min

Mavzularni alohida emas, tizim sifatida tushuntiring

Student tushunishi kerak: oddiy CRUD endpoint hali tugallangan API emas. Real loyihada unga qidiruv, filter va sahifalash qo‘shiladi. Swagger esa shu tayyor API ni ko‘rsatish va tekshirishga yordam beradi.

Teacher iborasi: “Model yaratish — boshlanish. Yaxshi API qilish uchun unga boshqaruv va qulayliklar ham qo‘shiladi.”
3-qadam · model 8–10 min

Course modelini studentlar bilan birga loyihalang

Model fieldlarini shunchaki diktovka qilib bermang. Har bir field nima uchun kerakligini ayting. Shunda keyingi search, filter va ordering qayerga qo‘llanilishini ham student o‘zi ko‘ra boshlaydi.

Faqat CRUD bilan cheklanib qolmang. Field tanlashda keyinchalik qaysi maydonlarda qidiruv va filtr qilish mumkinligini ham ko‘rsatib boring.
4-qadam · amaliy yozish 15–20 min

Course uchun CRUD, search, filter va pagination ni yozdiring

Bu qism darsning asosiy yadro qismi. Studentlardan serializer, view yoki viewset, url va swagger natijasini bittadan ko‘rsatishni talab qiling. Endpointlar ishlayotganini faqat kod bilan emas, response bilan ham tekshirtiring.

Amaliy natija: student bitta resurs uchun real ishlatiladigan API skeletonini mustaqil yozishga yaqinlashadi.
5-qadam · topshiriq 8–10 min

Dars oxirida mustaqil loyiha vazifasini bering

Mentor oxirida tayyor kodni ko‘chirib olish emas, balki mantiqni qayta tiklashga undashi kerak. Shu sabab topshiriqda student Course API ni boshidan o‘zi yozadi.

Teacher iborasi: “Bugungi dars sizga yo‘l ko‘rsatdi. Endi shu yo‘l bo‘yicha Course API ni mustaqil yakunlaysiz.”

Student nima qilishi kerak?
  • • Course modeli va serializer yozish
  • • CRUD endpointlar yaratish
  • • title va teacher_name bo‘yicha searching qilish
  • • level va is_active bo‘yicha filtering qilish
  • • list endpointga pagination qo‘shish
  • • Swagger orqali endpointlarni tekshirish
Mentor nimaga urg‘u beradi?
  • • Kod ishlashi kerak, faqat yozilgan bo‘lishi yetmaydi
  • • Query params amalda sinab ko‘rilishi kerak
  • • Search va filter farqini student og‘zaki tushuntirib bera olishi kerak
  • • Pagination response strukturasi ko‘rsatilishi kerak
  • • Swagger da endpointlar toza va tushunarli ko‘rinishi kerak
Chuqur tahlil

Mentor albatta aytib o‘tishi kerak bo‘lgan nuqtalar

Swagger — bu faqat chiroyli sahifa emas. U API ni tekshirish, endpointlarni tushuntirish va studentga response ko‘rinishini ko‘rsatish uchun kerak.
CRUD — bu asos. Lekin real backend ko‘pincha shu bilan tugamaydi. Query parametrlar qo‘shilmaguncha endpoint qulay bo‘lmaydi.
Searching ko‘proq matnli maydonlarda ishlatiladi. Filtering esa aniq qiymatlar bo‘yicha saralash yoki ajratish uchun ishlatiladi.
Pagination katta ma'lumotlarda response ni ixcham qiladi. Bu server va frontend uchun ham qulayroq ishlashni ta'minlaydi.
