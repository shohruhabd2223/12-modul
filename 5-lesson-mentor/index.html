Step by step

Dars o‘tish xaritasi

1-qadam · kirish 8–10 min

Authentication va permission farqini juda sodda misolda ochib bering

Dars boshida studentga shu ikki tushunchani ajratib bering: authentication — user kimligini aniqlash; permission — userga nima mumkinligini tekshirish. “Sen kimsan?” va “Senga nima mumkin?” degan ikkita savol juda yaxshi ishlaydi.

Bu joyda kodga shoshilmang. Avval mantiqni o‘rnating, keyin built-in permissionlarga o‘ting.
2-qadam · request oqimi 6–8 min

Request lifecycle ni qatorma-qator tushuntiring

Student request kelganda DRF ichida nima bo‘lishini bilsin: request keladi → authentication ishlaydi → user aniqlanadi → permission tekshiriladi → view ishlaydi yoki xato qaytadi.

3-qadam · built-in permissionlar 14–16 min

4 ta asosiy permissionni Product misolida ko‘rsating

Bu qism darsning yuragi. Student har bir permissionning qayerda ishlatilishini aniq ko‘rishi kerak.

AllowAny
Hamma kira oladi. Product list uchun mos.
IsAuthenticated
Faqat login qilgan user. Product create uchun mos.
IsAdminUser
Faqat admin. Product delete uchun mos.
IsAuthenticatedOrReadOnly
GET hammaga, yozish login qilganlarga.
Teacher uchun gap: “Built-in permissionlar ko‘p holatda yetadi. Dastlab aynan shu 4 tasini yaxshi ushlab olish kerak.”
4-qadam · kod bilan tushuntirish 16–18 min

Public list va protected create ni yonma-yon ko‘rsating

Studentga kontrast kerak: bitta endpoint public, ikkinchisi protected bo‘lsin. Shunda permission farqi aniq ko‘rinadi.

AllowAny
Public product list
class ProductListPublicView(APIView):
    permission_classes = [AllowAny]

    def get(self, request):
        products = Product.objects.all()
        serializer = ProductSerializer(products, many=True)
        return Response(serializer.data)
IsAuthenticated
Protected create
class ProductCreateView(APIView):
    permission_classes = [IsAuthenticated]

    def post(self, request):
        serializer = ProductSerializer(data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=201)
        return Response(serializer.errors, status=400)
Shu joyda studentga yana eslatib qo‘ying: authentication bo‘lmasa, permissiondan oldin ham user anonymous bo‘lib qoladi.
5-qadam · token auth 10–12 min

Token authentication ni minimal ko‘rinishda ulab ko‘rsating

Bu darsda JWT shart emas. Studentga token auth logikasini ushlatish kifoya: token olinadi → headerga yuboriladi → request.user aniqlanadi.

Install
INSTALLED_APPS → rest_framework.authtoken
Qisqa tartib
1. authtoken app qo‘shiladi
2. migrate qilinadi
3. DEFAULT_AUTHENTICATION_CLASSES yoziladi
4. obtain_auth_token URL ochiladi
5. Authorization header bilan yuboriladi
settings.py
Token authentication
REST_FRAMEWORK = {
    'DEFAULT_AUTHENTICATION_CLASSES': [
        'rest_framework.authentication.TokenAuthentication',
    ],
    'DEFAULT_PERMISSION_CLASSES': [
        'rest_framework.permissions.IsAuthenticated',
    ]
}
Mentor studentga aytsin: “Token bu user o‘rniga yuradigan maxsus kalit. Shu kalit bilan server seni taniydi.”
6-qadam · statuslar 10–12 min

200, 400, 401, 403 va 500 oilalarini Product API bilan bog‘lab ko‘rsating

Student faqat endpointni ishlatmasin, response statuslarga ham qarasin. Dars oxirida shu farqlarni aytib bera olishi kerak.

2xx
Muvaffaqiyat. Masalan 200 OK, 201 Created.
4xx
Client xatosi. 400, 401, 403, 404 shu oilaga kiradi.
5xx
Server xatosi. Odatda kod ichida kutilmagan muammo.
