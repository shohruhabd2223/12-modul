Dars maqsadi

Mentor dars oxirida nimaga erishishi kerak?

Auth fundamentals → JWT amaliyot
Student authentication ni “login qilish” degan bitta tushuncha sifatida emas, balki user kimligini aniqlash jarayoni sifatida anglab olishi kerak.
Student dars oxirida Session, Basic, Token, JWT farqini ayta olishi va Swagger’da JWT access token bilan protected endpointni test qila olishi kerak.
Eng muhim pedagogik nuqta

Authentication va Permission farqini albatta ajrating

Dars boshidagi urg‘u
Authentication
“Bu user kim?” degan savolga javob beradi. Natija: request.user.
Permission
“Bu user nima qila oladi?” degan savolga javob beradi. Natija: GET/POST/DELETE ruxsat masalasi.

Mentor studentlarga boshida aytsin: 401 ko‘pincha auth muammo, 403 esa ko‘pincha permission muammo.

Step by step

Dars o‘tish xaritasi

1-qadam · kirish 8–10 min

Authentication tushunchasini sodda misol bilan ochib bering

Dars boshida studentga “auth = login” emasligini tushuntiring. Masalan: universitetga kirishda ID karta ko‘rsatish — bu authentication; auditoriyaga kirishga ruxsat bor-yo‘qligi — bu permission.

Bu bosqichda Session, Basic, Token, JWT nomlarini faqat sanab o‘ting. Farqlarini keyingi bosqichlarda batafsil ochasiz.
2-qadam · auth turlari 12–15 min

Qolgan auth turlarini ketma-ketlik bo‘yicha tushuntiring

Mentor Session → Basic → Token → JWT tartibida tushuntirsin. Har biri uchun “request bilan nima ketadi?”, “server nimani tekshiradi?”, “qayerda ishlatish qulay?” savollarini ishlating.

Session
Cookie + server session
Basic
Har requestda credential
Token
Bitta statik token
JWT
Access + refresh token
Basic auth’ni production uchun yaxshi variant deb aytmang. Uni test va sodda tushuncha sifatida ko‘rsating.
3-qadam · JWT core 10–12 min

JWT ning 3 qismi va access/refresh farqini aniq ajrating

Student JWT ni faqat “uzun token” deb qabul qilmasligi kerak. Header, payload, signature qismlarini ko‘rsating. So‘ng access token va refresh token farqini alohida chizing.

Header
Algoritm va token turi
Payload
user_id, exp, token_type
Signature
Token buzilmaganini tekshiradi
Teacher uchun gap: “Access bilan API ga kirasiz, refresh bilan yangi access olasiz.”
4-qadam · flow 12–15 min

Login → access/refresh → protected request → refresh oqimini butun zanjir sifatida ko‘rsating

Bu darsning yuragi JWT flow. Student token olish, ishlatish va yangilashni bir butun jarayon sifatida ko‘rishi kerak.

1. Login request
2. Access + Refresh
3. Bearer access bilan API
4. Access expire
5. Refresh orqali yangilash
Studentlar ko‘pincha refresh token bilan protected endpointga kira olaman deb o‘ylashadi. Shu xatoni shu yerning o‘zida to‘xtating.
5-qadam · swagger amaliyoti 12–15 min

Swagger’da JWT token ishlatishni amaliy ko‘rsatib bering

Mentor bu joyda studentga aynan quyidagi tartibni ko‘rsatishi kerak: POST /api/token/ → access token olish → Authorize → Bearer access_token → protected endpointni test qilish.

Mentor urg‘usi
Studentga ayting: “401 bo‘lsa token muammo, 403 bo‘lsa permission muammo.”
Bu joyda lesson sayt ichidagi Swagger slaydlaridan foydalanib, access tokenni qaysi joyga yozish va Bearer prefiksi qachon kerakligini alohida ko‘rsating.
6-qadam · mustaqil ish 10–12 min

Swagger yordamida JWT tokenni ishlatib tahlil qildiring

Darsning mustaqil ish qismida student kod yozmaydi, balki tizimni tahlil qiladi. Vazifa — Swagger ichida token olib, Authorize qilib, protected endpointlarni sinab ko‘rish va 401/403/200 holatlarini farqlash.

1. Token olish
POST /api/token/ ni ishlatadi
2. Authorize
Bearer access_token kiritadi
3. Protected API
Try it out bilan request yuboradi
4. Tahlil
401, 403, 200 sababini aytadi
Mentor uchun urg‘u: “Bu topshiriqda maqsad tokenni yodlash emas, ishlash mantiqini tushunish.”
7-qadam · homework 5–7 min

Uyga vazifada auth turlarini solishtirish va JWT flow ni chizdiring

Homework da student ikki narsani topshiradi: 1) Session, Basic, Token, JWT solishtirish jadvali 2) Login → access/refresh → protected request → refresh oqimini o‘z qo‘li bilan yozilgan map ko‘rinishida topshirish.

1-topshiriq
4 ta auth turini jadval ko‘rinishida taqqoslash
2-topshiriq
JWT ishlash jarayonini ketma-ket map ko‘rinishida yozish
Tekshiruv mezoni: student 401 va 403 farqini ayta olishi, access va refresh rolini chalkashtirmasligi va Swagger’dagi ishlatish tartibini tushuntira olishi.
