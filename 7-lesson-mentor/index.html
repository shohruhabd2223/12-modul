Dars maqsadi

Mentor dars oxirida nimaga erishishi kerak?

Local → Production → Render
Student local loyiha va production loyiha orasidagi farqni anglab olishi kerak. Ya’ni kod yozish bilan ish tugamasligi, internetga chiqish uchun qo‘shimcha sozlamalar kerakligini tushunishi kerak.
Student dars oxirida DEBUG, ALLOWED_HOSTS, STATIC_ROOT, WhiteNoise, CORS, build/start command kabi eng kerakli deploy nuqtalarini ayta olishi va Render deploy oqimini mustaqil tushuntira olishi kerak.
Eng muhim pedagogik nuqta

“Deploy” tushunchasini “internetga chiqarish” deb sodda tarjima qiling

Dars boshidagi urg‘u
Local
“Bu loyiha faqat mening kompyuterimda ochilyapti” degan holat.
Production
“Bu loyiha serverga chiqdi va boshqalar ham ishlata oladi” degan holat.

Mentor studentlarga boshida aytsin: deploy — bu shunchaki upload emas; static, server va settings to‘g‘ri ishlashi ham shu jarayonning ichida.

Step by step

Dars o‘tish xaritasi

1-qadam · kirish 8–10 min

Production tushunchasini sodda misol bilan ochib bering

Masalan: daftarda yozilgan loyiha hali tayyor mahsulot emas. Uni hammaga ko‘rsatish uchun taxtaga chiqarish kerak. Xuddi shunday, local project deploy qilinmasa foydalanuvchi ko‘ra olmaydi.

Bu bosqichda database va .env ni murakkablashtirmang. Asosiy fokus — projectni serverga chiqarish mantiqi.
2-qadam · paketlar 10–12 min

Gunicorn, WhiteNoise va CORS headers vazifasini ajratib tushuntiring

Mentor har bir paket uchun “bu qaysi muammoni hal qiladi?” savolini ishlatsin. Student shuni tushunsin: Gunicorn — server, WhiteNoise — static, CORS headers — frontend bilan aloqa.

Gunicorn
Django app’ni server sifatida ishga tushiradi
WhiteNoise
Static fayllarni beradi
CORS headers
Frontend requestlariga ruxsat beradi
Studentga ayting: deploydagi ko‘p xatolar aynan static yoki host/cors sozlamasidan keladi.
3-qadam · settings 12–15 min

DEBUG, ALLOWED_HOSTS va STATIC_ROOT ni alohida urg‘u bilan ko‘rsating

Bu darsning eng markaziy settings qismi shu. Student shuni aniq bilishi kerak: DEBUG false, Render domeni ALLOWED_HOSTS’da, static esa collectstatic orqali yig‘iladi.

DEBUG
Production da False bo‘ladi
ALLOWED_HOSTS
Render domeni yoziladi
STATIC_ROOT
Static yig‘iladigan joy
Teacher uchun gap: “Static chiqmasa, ko‘pincha STATIC_ROOT yoki collectstatic ni tekshiramiz.”
4-qadam · CORS 10–12 min

CORS ni frontend va backend alohida turgan holat bilan bog‘lang

Student ko‘pincha CORS’ni yodlaydi, lekin mohiyatini tushunmaydi. Tushuntiring: frontend boshqa origin’da turgani uchun browser ruxsat so‘raydi; shu joyda CORS kerak bo‘ladi.

1. Frontend boshqa joyda
2. Browser tekshiradi
3. Backend ruxsat beradi
4. API ishlaydi
Studentlarga ayting: “CORS yo‘q bo‘lsa backend ishlayotgan bo‘lsa ham browser requestni bloklashi mumkin.”
5-qadam · Render amaliyoti 12–15 min

Render dashboard mantig‘iga o‘xshatib deploy oqimini ko‘rsating

Bu bo‘lim endi Swagger uslubida emas. Student Render’ni dashboard sifatida ko‘rsin: chapda workspace va servislar, o‘ngda service overview, deploy holati, logs va settings mantig‘i.

Mentor urg‘usi
Studentga Render’ni faqat “deploy tugmasi” sifatida emas, balki dashboard sifatida ko‘rsating: service holati, deploy tarixi, logs va settings bir joyda bo‘ladi.
Bu vizual endi Swagger’ga o‘xshamaydi. Chapda workspace/service navigatsiyasi, o‘ngda service overview va deploy status ko‘rinishi Render dashboard mantig‘iga yaqinlashtirildi.
6-qadam · mustaqil ish 10–12 min

Loyihani 1 marta deploy qildirib, natijasini tahlil qildiring

Darsning mustaqil ish qismida student kamida 1 marta loyihasini serverga chiqaradi va ishlash holatini tahlil qiladi. Vazifa — loyiha ochildimi, static chiqdimi, qayerda xato bo‘ldi — shuni aniqlash.

1. Deploy
Loyihani serverga chiqardi
2. Tekshiruv
Live linkni ochib ko‘rdi
3. Tahlil
Nima ishladi, nima xato bo‘ldi
Mentor uchun urg‘u: “Bu topshiriqda maqsad faqat deploy emas, natijani o‘qish va xatoni ko‘ra olish.”
7-qadam · homework 5–7 min

Uyga vazifada 3 marta deploy qilib, har safargi natijani topshirtiring

Homework da student kamida 3 marta loyihasini serverga deploy qiladi va har bir urinishdagi natijani ustozga yuboradi. Bu orqali real deploy tajribasi hosil bo‘ladi.

1-urinish
Deploy qilib ko‘rish
2-urinish
Xatoni tuzatib qayta deploy
3-urinish
Yakuniy ishlagan natija
Tekshiruv mezoni: student build/start commandni tushunishi, static va host/cors muammolarini ko‘ra olishi va deploy natijasini tahlil qila olishi.
