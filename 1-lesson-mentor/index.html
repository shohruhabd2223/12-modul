Step by step

Dars o‘tish xaritasi

1-qadam · kirish 8–10 min

DRF va API tushunchasini sodda analogiya bilan ochib bering

Slide 2 va 3 da asosiy vazifa — kodga shoshmasdan oldin API nima va DRF nimani osonlashtiradi degan savollarga javob berish. Restoran/ofitsiant analogiyasini ishlating: client buyurtma beradi, API tashiydi, backend javob tayyorlaydi.

Bu bosqichda studentga HTTP, JSON, endpoint so‘zlari hali qiyin bo‘lishi mumkin. Avval ko‘prik, elchi, ofitsiant kabi o‘xshatishlar bilan mustahkamlang.
2-qadam · setup 12–15 min

PyCharm setup paytida xatolarni oldindan to‘xtating

Slide 4 studentlar eng ko‘p adashadigan joy. Mentor har bir bolada Django tanlanganini, app va root to‘g‘ri yozilganini tekshirsin.

Biror student noto‘g‘ri project ochsa, keyingi kodlar bilan mos kelmay qoladi. Shu sabab bu qadamda sekinroq boring.
3-qadam · settings.py 6–8 min

rest_framework va app ni settings ga qo‘shish nega kerakligini ayting

Slide 5 da student faqat kodni ko‘rmasin, ma’nosini ham tushunsin: rest_framework — DRF imkoniyatlarini yoqadi, app — o‘zimiz yozayotgan kod ishlashi uchun kerak.

Mentor iborasi: “Biz hozir Djangoga yangi imkoniyat qo‘shyapmiz. Ya’ni project ichiga DRF ni ulayapmiz.”
4-qadam · CRUD flow 20–25 min

Model → Serializer → ViewSet → Router zanjirini butun oqim sifatida ko‘rsating

Slide 6 darsning yuragi. Bu yerda student alohida fayllarni emas, ularning o‘zaro ishlashini ko‘rishi kerak. Har birini ketma-ket tushuntiring:

Model
Ma’lumot bazada qanday saqlanishini belgilaydi.
Serializer
Modelni JSON ga aylantiradi va kelgan datani tekshiradi.
ViewSet
CRUD logikasini bir joyga jamlaydi.
Router
Endpointlarni avtomatik ochib beradi.
Teacher uchun gap: “Model datasini yaratadi, serializer uni tashqariga chiqaradi, viewset boshqaradi, router esa eshik ochadi.”
5-qadam · endpointlar 8–10 min

GET, POST, PUT, DELETE ni real misol bilan gapirtiring

Slide 7 da methodlarni yodlatmang, ishlatib ko‘rsating: GET — ko‘rish, POST — yaratish, PUT — yangilash, DELETE — o‘chirish.

GET /person/ → barcha ma’lumotlar
POST /person/ → yangi ma’lumot qo‘shish
GET /person/1/ → bitta object
PUT / DELETE /person/1/ → o‘zgartirish yoki o‘chirish

7-qadam · drf-yasg 10–12 min

9-betdagi yangi Swagger ishlatish tartibini faqat drf-yasg bilan ko‘rsating

Teacher guide ham endi lesson saytdagi yangilikka mos bo‘lishi kerak. Shu sabab mentor faqat drf-yasg ni ishlatib ko‘rsatadi: install qilish, INSTALLED_APPS ga qo‘shish, schema_view yaratish va /swagger/ sahifani ochish.

Install komanda
pip install drf-yasg
Qisqa tartib
1. drf-yasg ni install qiling
2. settings.py ga drf_yasg ni qo‘shing
3. root/urls.py da schema_view yozing
4. /swagger/ URL ni oching
5. Try it out → Execute bilan sinang
settings.py
drf_yasg qo‘shilishi
INSTALLED_APPS = [
    'rest_framework',
    'drf_yasg',
    'app',
]
root/urls.py
Minimal swagger sozlash
from django.contrib import admin
from django.urls import path, re_path, include
from rest_framework import permissions
from drf_yasg.views import get_schema_view
from drf_yasg import openapi

schema_view = get_schema_view(
    openapi.Info(
        title="Student API",
        default_version='v1',
        description="Student CRUD API hujjati",
    ),
    public=True,
    permission_classes=[permissions.AllowAny],
)

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('app.urls')),
    re_path(r'^swagger(?P<format>\.json|\.yaml)$', schema_view.without_ui(cache_timeout=0), name='schema-json'),
    path('swagger/', schema_view.with_ui('swagger', cache_timeout=0), name='schema-swagger-ui'),
]
Mentor studentga aytsin: “Bizga bu dars uchun drf-yasg ning o‘zi yetadi. Swagger sahifani ochamiz va endpointlarni shu yerdan tekshiramiz.”
